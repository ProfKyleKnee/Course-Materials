## Pedagogical goal

Helps Calc 1 students synthesize first- and second-derivative sign information into a curve sketch, mirroring Kyle's exam format (students get derivative number lines and must produce a possible graph). Used primarily for live classroom demonstration; also used by students on phones/tablets, so responsive layout is a real constraint. The applet never shows students the underlying function formula — functions exist only for internal validation. Tiers are jumpable in any order, not a forced progression. Locked framing tagline: "Let's use information from the 1st and 2nd derivatives to build a possible sketch of the function."

## Design decisions log

- Prior sessions: six tiers scoped and named for the mathematical concept rather than a difficulty number — Baseline (clean cubic), Faker (false critical point), Impostor (false inflection point), The Gap (two vertical asymptotes), Corner (non-differentiable seam), Capstone (all skills combined, no formula shown).
- Prior sessions: clickable interval-segment feature deferred in favor of x-axis labels. Engine only supports vertical-asymptote domain breaks, not removable holes.
- Prior sessions: square-root notation uses CSS `text-decoration: overline` on the digit (Unicode combining characters rendered unreliably). Domain-break ticks show the actual x-coordinate in italics, not a bare "u." Pause duration during animation is fixed at 1 second regardless of playback speed. Label badges fade via CSS opacity transition, not instant disappearance. Number-line spacing is even/non-proportional for busy tiers, capped at four marked values per line.
- This session: root-caused the header/panel misalignment to `.main-grid`'s `grid-template-columns: 62% 38%` — the two percentages already summed to 100% of the container, so the 18px column gap pushed the second column 18px past the container's right edge. Fixed by switching to `62fr 38fr`, which correctly reserves space for the gap. Verified 0px difference between header and panel right edges at four viewport widths (1024–1400px).
- Prior session: header kicker/title/tagline sized up from 10px/17px/13px to 12px/23px/15px (mockup "Option C" of four sizes shown), with tab-pill label text nudged from 12.5px/10px to 13px/10.5px to stay proportional. - This session (2026-08-14): built a dedicated `curveSketch` card-tile animation (`csTileSVG`/`csStartSpin`/`csStopSpin` in `js/app.js`, CSS comment block in `css/styles.css`) that echoes the applet's own two-pass reveal order: on hover, a rough straight-line polyline through the cubic's own local-max/inflection/local-min vertices sketches itself in first via a `stroke-dashoffset` reveal (`getTotalLength()`-based, same technique as the Polar Graphing tile), and only *after* that one-time reveal finishes does the shape start bending back and forth into the real cubic (`x^3 - 3x`, the Baseline tier's own function) and back — mirroring "shape first, concavity after." Timings were slowed down once at Kyle's request (`CS_SKETCH_MS` 550→1100, `CS_HOLD_MS` 500→900, `CS_MORPH_MS` 700→1300). `js/data.js`'s `a-c1-45` row now carries `tileType: 'curveSketch'` instead of a `curve` field.
- **Gotcha hit this session**: `curve-sketching-v13.jsx` stores its non-ASCII punctuation (em dashes, middot) as literal `—`/`·` *escape-sequence text* in a few spots rather than real UTF-8 glyphs (inconsistent with other lines in the same file that do use real glyphs) — a plain-text find/replace typed with a real "—" character silently fails to match those lines. When editing a block containing one, either match it with the literal 6-character `\` `u` `2` `0` `1` `4` sequence, or do the edit by line-index slicing (e.g. a small Node script reading/writing the file) instead of string matching.
- This session: rebuilt the shipped bundle with a real `esbuild --bundle --format=iife --jsx=automatic` pass against `react@19`/`react-dom@19` (the file already used real ES-module `import` syntax, same build shape as Quadric Surfaces) rather than hand-editing the compiled output — Node/npx were available this session, unlike the Polar Graphing/Taylor Series sessions.
- This session (2026-08-15): reworked the `curveSketch` tile's timing and cycle shape after two rounds of Kyle's feedback. The pause between the line-sketch finishing and the concavity morph starting went 900ms → 200ms → 100ms → 50ms (kept nonzero throughout — a "short but present" beat, not eliminated). More importantly, the cycle itself was restructured: the original version bent the shape into the curve and then bent it *back* to straight before looping, which read as a continuous back-and-forth wobble; Kyle's actual ask was sketch → pause → concavity morph → pause → **restart from a blank sketch**, matching the applet's own two-pass reveal replaying from scratch each loop rather than reversing. `CS_CYCLE_MS` is now `CS_SKETCH_MS + CS_HOLD_MS + CS_MORPH_MS + CS_HOLD_MS`, and the wrap-around is a hard cut (the sketch phase's first frame snaps `d` back to the straight shape and re-hides it via dashoffset in the same frame — there's no reverse-morph phase left in the code at all.
- This session: combined the graph's standalone "Click Play to reveal how the first derivative shapes this curve" instruction line with the locked pedagogical tagline (which used to sit above the tier-tab selector) into one line — "Click **Play** to reveal how the 1st and 2nd derivatives affect the shape of the curve." — positioned directly above the Play button/progress slider instead of above the graph, and shown only before the student starts (same condition as before). The old tagline paragraph and the old graph-top instruction-text were both deleted outright, not just hidden, so there's only one instructional string in the DOM now. `.instruction-text` also picked up `white-space: nowrap` + a 14px→13px size trim to reliably fit on one line at normal widths, and 18px of top margin was added after Kyle flagged it sitting too close to the speed-preset/Reveal Graph row above it.
- **This session — real bug found and fixed, not just requested**: while building the narrow-viewport fix Kyle asked for, `.main-grid`'s columns (`62fr 38fr`, and the new mobile breakpoint's `1fr`) were overflowing the viewport on phones — "Reveal Graph" and "2nd Derivative Pass" were both getting clipped past the right edge with a page-level horizontal scrollbar. Root cause: an `Nfr` grid track's *implicit minimum size is `auto` (its content's natural width), not `0`* — `.graph-card`'s own intrinsic width was stretching the whole grid past 375px instead of shrinking to fit it. Fixed by switching both the desktop and mobile column definitions to `minmax(0, Nfr)`. The two derivative-pass `<input type="range">` sliders had the identical bug one level down (flex children default to `min-width: auto`, i.e. their own intrinsic width, inside `.slider-row`) and needed the same `min-width: 0` fix. This is the same *shrink-to-fit needs an explicit minimum* family of gotcha `.claude/rules/applets.md` already documents for flexbox (`min-height: 0`) — worth checking for the CSS Grid version too on any applet with a multi-column layout that's expected to go responsive.
- This session: added a `720px` breakpoint (`.main-grid` → single column, `.app-outer`/`.app-card-body` padding tightened, `svg.graph` height 380px→300px) and a `480px` breakpoint (`.instruction-text` allowed to wrap instead of forcing `nowrap`) as a first pass at real mobile responsiveness — verified clean (no overflow, no console errors) at 375px, 820px, and desktop widths. This is a first pass, not a full mobile redesign; see Open threads.

## Interaction & animation details

(Carried from prior sessions — not re-verified in detail this session beyond the round-trip test below.)
- Two-pass reveal: 1st Derivative Pass animates the curve using only increasing/decreasing behavior; 2nd Derivative Pass adds concavity. Play button pulses to draw attention before first use.
- Domain-break ticks and sign-row labels pulse (ring animation, 0.8s ease-out ×2) when clicked/reviewed, with label badges fading in/out via opacity transition.
- Tab switching uses a sliding "thumb" behind the active tab pill (position/size tracked via `offsetLeft`/`offsetWidth` of the active button, animated via CSS transition on `left`/`top`/`width`/`height`).

## Technical build notes

- **Stack**: React + esbuild, bundled to a single self-contained HTML file (`curve-sketching-v13.html`) for offline/LMS delivery. No external requests at runtime.
- **This handoff's source files**: The project has only ever kept the compiled HTML as its working file — there was no separately maintained `.jsx` source. For this handoff, the JSX/JS application code was extracted from the bundle (`src/main.jsx`'s compiled output lives between the `// src/main.jsx` marker and the final `root.render()` call) and mechanically decompiled back into JSX syntax using a Babel AST transform (converting `jsx()`/`jsxs()` calls back into `<Element>` syntax). **This is a reconstruction, not the original source** — variable names, structure, and logic are faithful (it's a direct AST-level inverse of the compile step), but formatting/comments are not preserved from any "true" original since none was ever saved separately.
- **Verification of the reconstruction**: re-bundled the decompiled `.jsx` with esbuild (`jsx: "automatic"`), reassembled it into a full HTML page with the extracted stylesheet, and ran it through Playwright: zero console errors on load, zero React key warnings, and a spot-check across three tiers (Baseline, Faker, Impostor) including a triggered play animation — all pixel- and behavior-identical to the v13 build. One real bug was caught and fixed during the reconstruction itself: two `.map()` calls return a `<>...</>` Fragment shorthand, which can't carry a `key` prop — these needed the explicit `<Fragment key={...}>` form instead, or React throws a missing-key warning on those lists.
- **Files delivered**: `curve-sketching-v13.jsx` (component source, needs React 18+/`react-dom/client`) and `curve-sketching-styles.css` (the full stylesheet — the JSX alone will not render correctly without it). To get back to a working single-file HTML build, bundle the `.jsx` with esbuild using `jsx: "automatic"` and inline both the resulting JS and the CSS into an HTML shell (same pattern as all of Kyle's other applets).
- Uses SymPy (offline, prior sessions) for symbolic math verification and Playwright for UI verification; no runtime dependency on either.
- Shares the Cloud Pastel visual system and header design (adopted from the Quadric Surface Explorer) with the rest of Kyle's applet suite.
