# Secant-to-Tangent Line — Project Spec

_Course: Calc 1_
_Folder: Applets/Calc 1/Secant-to-Tangent Line/_
_Last updated: 2026-08-15_

## Current status

Built, wired into the main site (`js/data.js` id `a-c1-31`, Calc I Unit 2), and migrated to the canonical full-viewport header/footer pattern on the `SecantToTangent-Wiring` branch. The applet visualizes secant lines collapsing into the tangent line as h → 0, connecting the geometric picture to the formal limit definition of the derivative. Since migration, the layout has gone through several live rounds with Kyle: notation-toggle crossfade, a right-column-then-side-column redesign (Table/Derivation moved off to a fixed-width side column so opening them never resizes anything else), a derivation-overflow fix, and a pass on animation timing/defaults/styling (see decisions log below for specifics). As of this checkpoint, no open bugs — the last round (notation/tangent/rise&run fade timing, right-click-open-in-new-tab, card desc length, slider default, and the Riemann-Sum-matched f(x) pill) has been implemented and locally verified but not yet re-confirmed by Kyle. Next session should start by asking whether that round landed correctly before assuming it's settled.

## Pedagogical goal

Make the transition from secant slope to derivative concrete and dynamic, rather than a static textbook figure. Students should be able to watch the Difference Quotient numerically converge toward f′(a) as h shrinks, see the secant line visually collapse into the tangent line, and connect the geometric picture (Rise & Run triangle) to the symbolic definition (stacked-fraction formulas, limit notation) side by side. Two notation conventions (a, a+h and x, a) are both supported since students encounter both in textbooks.

## Design decisions log

- Initial planning session: layout locked as full-width graph → f(x) banner → 5-card readout row → slider/play/inputs row → toggle row (Rise & Run / Tangent / Table) → fixed reference table → collapsible derivation panel. Colors: blue curve `#3B4FC2`, secant `#C1556B`, tangent/f′(a) `#C98F3E`, Rise & Run `#3FA671`. Two-notation toggle (`a, a+h ⇄ x, a`) shows both states as text, not icon-only.
- Readout row: Option A chosen (Difference Quotient and f′(a) as two separate adjacent cards, not nested) — direct side-by-side numeric comparison was judged the clearest way to show DQ converging toward f′(a).
- Tangent toggle animation: 960ms, `cubic-bezier(0.4,0,0.2,1)` (no overshoot), tangent line fade-in simultaneous with the readout row's cards resizing (4 cards compress, f′(a) card expands from width 0). Fully reversible. Approved via a standalone HTML/CSS timing demo before being carried into the real build.
- Table: fixed (not live during Play), 9 rows, log-spaced (h = 3, 2, 1, 0.5, 0.25, 0.1, 0.05, 0.01, 0.001), sign-aware (mirrors to match whichever side the student's current h is on), last row highlighted.
- Rise & Run: draws on the current secant (not the tangent), P=(a,f(a)), Q=(a+h,f(a+h)), right angle at (a, f(a+h)). Hides as a single unit (legs + corner mark + labels) once the triangle drops below ~20px on screen, rather than disabling the feature outright — so it reappears automatically if the student zooms in.
- Custom function input: mathjs is not available in the build sandbox (no network access to install it), so a hand-rolled recursive-descent expression parser was written instead (supports `+ - * / ^`, parens, `sin/cos/tan/exp/ln/log/sqrt/abs`, implicit multiplication, constants `e`/`pi`). Validated against known values before use.
- f′(a) is computed numerically (central difference, ε=1e-6), independent of the student-controlled h — not symbolically — since custom typed expressions have no symbolic derivative available. Kyle confirmed this is an acceptable and visually indistinguishable substitute.
- Domain handling: `a` is clamped into the function's domain (e.g. ln(x) needs a>0, √x needs a≥0); `h` is clamped via binary search so `a+h` never leaves the domain — dragging or animating toward a domain boundary stops there rather than going undefined.
- Bug-fix round (post-build): root-caused a runaway-h bug to an auto-adjust-camera-during-drag feature that could compound on itself mid-drag. Resolution: autofit is now a purely manual button press — nothing auto-recenters the camera during dragging, typing, or committing values.
- Same round: fixed a real geometry bug in the Rise & Run right-angle corner mark (was mispositioned for one of the two secant orientations); fixed the Play button getting "stuck" when paused very close to h=0 (an overly tight guard blocked resuming); replaced the original log/exponential Play easing with a mostly-linear curve that only decelerates in the final ~20% of the sweep, after Kyle reported the animation ran too fast to see anything meaningful — this also fixed the echo trail appearing not to fade (echoes were bunching almost on top of each other in space under the old log easing, not actually failing to fade).
- Added: manual "Show Secant Lines" / "Clear Secant Lines" toggle, tied to dragging and the slider (not typed input) — lets students manually leave a fading trail (same visual mechanic as Play's animated trail, capped at 5 lines) outside of just hitting Play.
- Added: x/y axes (light gray, drawn under the curve, only rendered when the origin is within the current view).
- Added: click-and-drag canvas panning (same convention as the Taylor's Theorem applet) and scroll-wheel zoom, cursor-anchored, with page-scroll correctly suppressed while hovering the graph.
- Fixed: `preserveAspectRatio="none"` was missing on the SVG, which caused browser letterboxing — this was the root cause of both a visual bug (curve appearing to stop short of the graph edges) and a drag-tracking bug (dragging past the visible curve). Also added an explicit clamp so dragging the pointer past the graph box itself can't pull the point beyond the visible x-range.
- Fixed: the custom-expression parser was missing inverse trig functions (`arctan`/`atan`, `arcsin`/`asin`, `arccos`/`acos`) — added.
- Fixed: `x^(1/3)` (and other odd-root fractional exponents) returned NaN for negative x, because JavaScript's `Math.pow` doesn't extend real odd roots to negative bases the way math does. Added a `safePow` that recognizes exponents matching a small rational fraction (denominator ≤ 12) and computes the correct real-valued odd root.
- Play/manual-trail integration: hitting Play now automatically flips the manual toggle to "Clear Secant Lines" (since Play always produces a trail). While Play is actively running, clicking the button only clears the visible trail — it can't flip back to "Show" until Play is stopped (Play "owns" the trail while running). After Play stops (paused or finished), the button stays on "Clear Secant Lines," and normal toggle behavior (Clear → Show) only resumes once Play is off. This makes Play and manual dragging feel like one continuous trail-drawing feature rather than two disconnected systems.

## Interaction & animation details

- **Tangent toggle:** 960ms `cubic-bezier(0.4,0,0.2,1)`, no overshoot, simultaneous line-fade + readout-row resize, fully reversible on toggle-off.
- **Play button:** sweeps h → 0 using a mostly-linear easing curve — constant speed for the first 80% of the sweep duration, then a gentle ease-out over the final 20% so the convergence moment stays legible instead of a blur. Total sweep ~6000ms, then a 500ms pause at h≈0.001 before looping back to whatever h was when Play was pressed. Dragging the point or moving the slider interrupts/pauses the animation immediately. Pressing Play again resumes from the *current* h (not the original session-start h) — this was an explicit correction after an earlier version got "stuck" trying to resume from a value below its own restart guard.
- **Echo trail (secant lines):** capped at 5, opacity ramps roughly 0.10 → 0.75 (newest brightest, oldest dropped entirely rather than lingering near-zero opacity). During Play, a new echo is pushed roughly every 1/6th of the sweep duration, and the trail clears at the start of every new sweep/loop. During manual dragging or slider use (only when the "Show/Clear Secant Lines" toggle is on), echoes are pushed on a ~120ms throttle to avoid flooding the array on every pixel of movement.
- **Show/Clear Secant Lines toggle:** off by default. Off→On: starts accumulating echoes on drag/slider interaction. On→Off (only possible while Play is NOT running): clears the trail and reverts to "Show." While Play is running, the button is locked in "Clear" mode — clicking it only wipes the currently-visible trail without stopping Play or reverting the label; new lines resume sketching immediately since Play's own echo-push loop is unaffected by the toggle. Starting Play always force-sets the toggle to "on."
- **Rise & Run hide behavior:** hides the entire overlay (both legs, corner mark, both labels) as a single unit once the triangle's on-screen diagonal drops below ~20px — not disabled, so it reappears automatically on zoom-in.
- **Canvas pan/zoom:** click-and-drag anywhere on the graph background pans the camera (grabbing the draggable point takes priority via `stopPropagation`, so the two gestures never conflict). Scroll wheel zooms centered on the cursor position, clamped to a sane scale range, with page-level scroll suppressed while hovering the graph. Autofit is a manual button only — nothing auto-recenters the camera in response to dragging, typing, or committing a value (this was a deliberate fix after auto-adjust-during-drag caused a runaway-h bug — see decisions log).
- **Domain clamping:** dragging or animating h toward a domain boundary (e.g. ln(x) as a+h → 0⁺) stops exactly at the boundary via binary search, rather than going undefined or discontinuous.

## Technical build notes

- Single self-contained HTML file (React bundled inline via esbuild, no external `<script src>` references, no CDN dependencies) — this is a hard requirement after an earlier round shipped as index.html + a separate bundle.js and broke as soon as the two files got separated.
- No mathjs available in the build sandbox (no network access to install packages at build time). Custom function expressions are parsed by a hand-rolled recursive-descent parser (in-file, not a dependency) supporting `+ - * / ^`, parens, implicit multiplication, `sin/cos/tan/exp/ln/log/sqrt/abs/atan/asin/acos` (plus `arctan/arcsin/arccos` aliases), and constants `e`/`pi`.
- `safePow(base, exp)` handles real-valued odd roots of negative bases (e.g. cube root of −8) by detecting when `exp` matches a small rational p/q (q ≤ 12) — covers essentially any exponent a student would type by hand, but exponents that aren't a clean small fraction will still fall back to `NaN` for negative bases (mathematically ambiguous territory, e.g. `x^(1/e)`), which is expected, not a bug.
- Camera/coordinate system: fixed pixel-space SVG (`viewBox="0 0 800 420"`, `preserveAspectRatio="none"` — required, its absence previously caused letterboxing that broke both curve rendering and drag math), with a `{cx, cy, scale}` camera object mapped via `worldToPx`/`pxToWorldX`/`pxToWorldY`-style helpers. Autofit, pan, and wheel-zoom all go through this same camera state.
- Playwright used throughout for verification (not just visual inspection) — geometry assertions (Rise & Run corner-mark bounding box vs. leg bounding box), functional assertions (echo counts by stroke-color selector, button label states, domain clamping via readout values), and regression checks after each fix. This caught several bugs that would have been easy to miss visually (e.g. the corner-mark math, the letterboxing distortion).
- Known non-issue worth flagging for future sessions: typing a function that's a pure vertical shift of the current one (e.g. `x^2 - 4` when already on `x²`) can look like nothing happened, because autofit re-centers on the new curve and a pure vertical shift lands in visually the same spot after re-centering. Confirmed via debugging that the underlying state and math are actually updating correctly in this case — not a bug.

## Post-migration layout/timing rounds (SecantToTangent-Wiring branch)

- Notation toggle (`a, a+h ⇄ x, a`) crossfades instead of snapping — a `Fade`/`FadeTspan` helper pair wraps every notation-dependent label (graph labels, readout cards, table headers, the derivation panel, the slider caption, the fused-input prefix) rather than interpolating the label straight into a string, so the toggle reads as a transition. Originally 160ms per phase; bumped to 480ms per phase (~960ms round trip) after Kyle felt it was still too fast next to the Tangent toggle's reveal — see the 960ms note below.
- Layout went through three real directions before landing: a right-column mockup (rejected — just relocated the same vertical stack into a narrower space, didn't fix anything), a full-width detail row below the graph+controls (rejected in favor of a persistent side column), and the current one — graph on top with the function input/readouts/slider/Rise & Run/Tangent all stacked underneath it in one main column, Table and Formula & Derivation living in a **fixed-width** side column (260px) with their own collapsible headers. Explicitly fixed-width, not resizing on open/close — an earlier version shrank the graph and widened the side column when a panel opened, which Kyle rejected as unnecessary once the panels' own content was made compact enough to fit a constant width.
- Real bug found and fixed: the "Definition of the derivative" equation (`f '(a) = lim_{h→0} [fraction]`) overflowed past the side column's right edge when inline — fixed by putting the fraction on its own centered line below `f '(a) = lim_{h→0}` instead of trying to fit both on one line. `Frac`'s num/den spans also got `whiteSpace: 'normal', overflowWrap: 'break-word'` as a defensive backstop.
- Play button moved to the left of the h-slider (was: slider, then Play, then Show Secant Lines). Rise & Run / Tangent moved off their own row and onto the a=/h= input row, right-aligned via `justify-content: 'space-between'` against the inputs+notation-toggle group on the left.
- `ToggleBtn` (used by Rise & Run/Tangent) used to render fully neutral gray at rest, with color only appearing once toggled on — read as "the buttons lost their color" since there was nothing to distinguish them from any other pill until clicked. Off state now keeps a colored border + colored text (a "ghost" outline of the button's own color); on state still fills solid. Transition bumped 200ms → 280ms.
- **960ms cubic-bezier(0.4,0,0.2,1) is the reveal timing standard for this applet** (matches the pre-existing Tangent-line/f'(a)-readout-card reveal from the original build) — applied to: the Table/Formula & Derivation side-column accordions (via always-mounted `max-height`+`opacity`, not conditional JSX mounting — conditionally mounting `{open && (<div>...)}` defeats a declared CSS transition since the element has no previous frame to animate from), and to the Rise & Run overlay and the tangent line itself. The tangent line and Rise & Run overlay had the **same latent bug**: both were gated by `{condition && (...)}`, so despite having a declared `opacity` transition, the element mounted/unmounted in the same render as the opacity flip and the "fade" never actually played (it just snapped, since there was no prior frame to transition from). Fixed by computing their geometry unconditionally and always rendering the element, with only `opacity` (not presence) driven by the toggle.
- Default `hVal` changed from `0.842` to `2` — the log-scaled slider thumb sat at ~21% from the left at the old default (already meaningfully "collapsed"-looking), which Kyle read as starting too far along with no documented pedagogical reason for that specific value. `autofit()` already runs on mount regardless of `hVal`, so no camera default needed to change alongside it.
- f(x) input restyled to match the Riemann Sum Explorer's Function control exactly (light-blue seamed prefix pill + white input, "Function" eyebrow label above, preset buttons in their own row below) — now documented as the cross-applet standard in `.claude/rules/applets.md`'s new "Function input pill" section. Only this applet has been retrofitted so far; Curve Sketching, Taylor Series, and Polar Graphing still use their own earlier styling.
- Applet-card grid/carousel tiles are now real `<a href>` elements (site-wide change, `js/app.js`'s `appletCardHTML()`) instead of `<div onclick>`, specifically so right-click → "Open link in new tab" works — a plain click still behaves identically (same-tab navigation) since that's the default behavior of clicking an anchor. Placeholder (`'#'`/unlinked) applet cards stay a plain `<div>` with no `href`, unchanged.
- Card description lengthened to reach the same ~4-line height as sibling Calc I applet cards (was noticeably shorter than Curve Sketching's/Newton's Method's/Riemann Sum's own descriptions).

## Second post-migration round (still SecantToTangent-Wiring)

- Default function/a/h changed from `x^2`/`a=1`/`h=2` to a curated demo Kyle landed on live: `f(x) = x(x-1)(x+1)` (a cubic, `functionKey: 'custom'` so no preset pill shows active), `a = 0.5`, `h = 0.672`. `autofit()` already runs on mount, so no camera default needed alongside it.
- `SLIDER_MAX_MAG` changed from a fixed `5` to `0.672` — matches the new default `h` exactly, which is what makes the slider thumb start pinned at the true left edge (`sliderPos = 0`) on load. Tradeoff: the slider itself can't represent `h` above 0.672 anymore (dragging left just pins at 0), but typing a larger `h` via the fused input, or dragging the point past that magnitude, still works — the slider just shows pinned-left in that case rather than clamping the actual value.
- Added auto-scaling tick marks to both axes (`niceStep`/`formatTick` helpers) — recomputes a "nice" 1/2/5×10ⁿ step from the current visible range every render, so spacing stays readable at any zoom instead of a fixed world-unit interval.
- Dragging the `a+h` point now always leaves a fading secant-line trail, not just when "Show Secant Lines" is pre-toggled on — `setManualTrailOn(true)` fires on drag-start (`onPointerDown`), same precedent as `startPlay()` already force-setting it. The slider's own echo-push still respects the toggle, unchanged.
- The "Definition of the derivative" box went back to one line (was split across two after the overflow bug) — fits by dropping to `fontSize: 11` and `whiteSpace: 'nowrap'` just for that row; verified zero overflow past the card edge via direct measurement, same technique used to catch the original bug.
- Table's `DQ` header renamed to `Diff. Quotient`.

## Notation-toggle jump (root cause, third round)

After the crossfade shipped, Kyle still saw a "jump" on toggle. Root cause: the opacity fade was working, but `Fade`'s wrapper had no fixed size, so it snapped to the new text's natural width the instant state flipped (e.g. `'h'` → `'x − a'`, or `'h ='` → `'x − a ='`) even though the *text itself* was fading smoothly — that width snap dragged along whatever sat next to it (the input field in `FusedInput`, the table column, etc.). Fixed by giving `Fade` an `alt` prop (the label's other possible value) and stacking both the current and alt strings, one always `visibility: hidden`, in the same CSS grid cell (`display: 'inline-grid'`, both children `gridArea: '1 / 1'`) — an element's intrinsic size follows the largest overlapping child, so the wrapper's width becomes a permanent `max(width(A), width(B))` regardless of which one is currently showing, and nothing around it moves anymore. `FadeTspan` (used inside the SVG `<text>` elements) didn't get this treatment — SVG text position is anchor+coordinate based, not box-model layout, so a changing string length there just changes how far the text extends from its anchor rather than shifting anything else, which isn't the same "jump" bug. Verified via direct width measurement (before/mid-transition/after) that `FusedInput`'s prefix box and the table's `<th>` columns now stay pixel-identical across a full toggle.

## Card tile

Replaced the generic curve+dot tile with a dedicated `tileType: 'secantTangent'` (`stTileSVG`/`stStartSpin`/`stStopSpin` in `js/app.js`, styled by `.st-tan`/`.st-sec`/`.st-dotP`/`.st-dotQ` in `css/styles.css`) — a dashed tangent "target" line that the solid secant line rotates into as h shrinks, with the secant's own point Q sliding along a real f(x)=0.4x² curve toward the fixed point P, using genuine secant-slope math (endpoints/position rewritten every animation frame), not decoration. Went through a follow-up round after the initial build: the tangent line is now bold (stroke-width 1.6→2.6, opacity 0.7→0.9, heavier dash) so it reads clearly as the target rather than a faint guide, and P moved from an arbitrary point (x=0.7) to the parabola's own vertex (x=0) so the tangent is horizontal — which then made "equal length on both sides of the vertex" a real, checkable requirement, satisfied by building the shared tangent/secant x-range symmetric around the vertex (`ST_HALF_SPAN` in both directions) rather than the old asymmetric "a little past Q's span" margin. That same wider range also lets the secant's own left-side extension visibly grow as h shrinks (a flatter line survives further before the tile clips it) without forcing the secant itself to be symmetric — only the tangent needed that constraint.
